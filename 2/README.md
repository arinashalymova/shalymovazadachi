# Сравнение производительности RabbitMQ и Redis

Проект для тестирования и сравнения двух популярных брокеров сообщений в идентичных условиях.

## Описание

Реализован автоматизированный стенд для нагрузочного тестирования `RabbitMQ` и `Redis` с возможностью:

- Варьирования размера сообщений (от 128 байт до 100 КБ)
- Изменения интенсивности потока (от 1000 до 10000 сообщений в секунду)
- Настройки количества производителей и потребителей
- Автоматического сбора метрик производительности

## Собираемые метрики

Для каждого теста фиксируются:

- Количество отправленных и принятых сообщений
- Пропускная способность (messages/sec)
- Задержки: средняя, 95-й перцентиль, максимальная
- Потери сообщений
- Остаток в очереди после завершения теста
- Факт деградации производительности

## Структура проекта

```
.
├── src/
│   └── benchmark.py          # Основной скрипт тестирования
├── docker-compose.yml         # Конфигурация контейнеров брокеров
├── requirements.txt           # Python зависимости
├── run.sh                     # Скрипт автоматического запуска
└── results/                   # Директория с результатами
```

## Быстрый запуск

### Полное тестирование

```bash
chmod +x run.sh
./run.sh
```

После выполнения в папке `results/` появятся файлы с результатами.

### Ускоренный режим

Для быстрой проверки работоспособности:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
docker compose up -d
python src/benchmark.py --quick --out-dir results_quick
```

Ускоренный режим тестирует только 2 размера сообщений и 2 уровня нагрузки по 10 секунд каждый.

## Ручная настройка

```bash
docker compose up -d rabbitmq redis
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/benchmark.py \
  --brokers rabbitmq,redis \
  --sizes 128,1024,10240,102400 \
  --rates 1000,5000,10000 \
  --duration 30 \
  --producers 2 \
  --consumers 2 \
  --out-dir results
```

## Параметры запуска

- `--brokers` - список брокеров для тестирования (через запятую)
- `--sizes` - размеры сообщений в байтах (через запятую)
- `--rates` - целевая интенсивность потока в msg/s (через запятую)
- `--duration` - длительность одного теста в секундах
- `--producers` - количество параллельных отправителей
- `--consumers` - количество параллельных получателей
- `--quick` - режим быстрой проверки

## Критерии деградации

Тест помечается как деградировавший, если:

- Размер очереди в конце превышает двойную целевую нагрузку
- 95-й перцентиль задержки превышает 200 мс
- Зафиксированы ошибки отправки
- Получено менее 98% от отправленных сообщений

## Требования

- Docker и Docker Compose
- Python 3.10 или выше
- 2 ГБ свободной оперативной памяти

## Результаты
