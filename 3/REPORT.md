# Отчёт: сравнение стратегий кеширования

## 1. Цель работы

Сравнить три стратегии кеширования на единой системе:

| Стратегия | Описание |
|-----------|----------|
| **Cache-Aside** | Чтение через кеш, запись в БД с инвалидацией |
| **Write-Through** | Чтение через кеш, запись синхронно в кеш и БД |
| **Write-Back** | Чтение через кеш, запись в кеш с отложенной записью в БД |

## 2. Архитектура

```
Генератор нагрузки → FastAPI (3 инстанса) → Redis → PostgreSQL
:8001 cache_aside
:8002 write_through
:8003 write_back
```

- **БД:** PostgreSQL 16, таблица `items`, 500 записей
- **Кеш:** Redis 7, отдельная DB для каждой стратегии
- **Приложение:** Python 3.12, FastAPI
- **Нагрузка:** единый скрипт для всех стратегий

## 3. Параметры тестирования

| Параметр | Значение |
|----------|----------|
| Длительность теста | 30 секунд |
| Целевой RPS | 200 |
| Воркеры | 8 |
| Пул ключей | 500 |

**Профили нагрузки:**

| Профиль | Read | Write |
|---------|------|-------|
| `read_heavy` | 80% | 20% |
| `balanced` | 50% | 50% |
| `write_heavy` | 20% | 80% |

При профиле `write_heavy` отправлено **24904 записи**, но в БД попало только **900** (18 пакетов по ~50 записей). Интервал flush: **2 секунды**, размер батча: **50**.

## 5. Выводы

### Для чтения (read_heavy)

**Лучший вариант:** Cache-Aside или Write-Back

- Cache-Aside: максимальный throughput (1191.4 req/s), минимальная задержка
- Write-Back: минимум обращений к БД (1087 ops), высокий hit rate (99%)
- Write-Through: 100% hit rate, но больше нагрузки на БД при записи

### Для записи (write_heavy)

**Лучший вариант:** Write-Back

- Write-Back: минимум нагрузки на БД (900 ops против 33709 у Cache-Aside)
- Буферизация записей в кеше снижает нагрузку на БД в **37 раз**
- Write-Through: гарантирует консистентность, но нагружает БД
- Cache-Aside: простота реализации, но максимум операций с БД

### Для смешанной нагрузки (balanced)

**Лучший вариант:** Write-Back или Write-Through

- Write-Back: минимум обращений к БД (850 ops), 100% hit rate
- Write-Through: баланс скорости и консистентности (16743 DB ops)
- Cache-Aside: простота, но 26067 операций с БД

## 6. Рекомендации

- **Cache-Aside** — простые системы с преобладанием чтения, где можно допустить временную рассинхронизацию
- **Write-Through** — когда важна строгая консистентность данных между кешем и БД
- **Write-Back** — высоконагруженные системы с интенсивной записью, где допустима небольшая задержка персистентности

### Компромиссы

| Стратегия | Производительность | Консистентность | Сложность |
|-----------|-------------------|----------------|-----------|
| Cache-Aside | Высокая при чтении | Средняя | Низкая |
| Write-Through | Средняя | Высокая | Средняя |
| Write-Back | Высокая | Низкая | Высокая |
