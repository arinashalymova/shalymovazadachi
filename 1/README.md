# Сервис для демонстрации SQL транзакций

Проект реализует три основных сценария работы с базой данных интернет-магазина с использованием транзакций.

## Используемый стек

- Python 3.12
- SQLAlchemy 2.x
- PostgreSQL 16
- Docker & Docker Compose
- psycopg2

├── docker/

## Реализованные сценарии

### Первый сценарий: создание заказа

Транзакция включает:
- Создание записи в таблице `orders`
- Добавление позиций заказа в `orderitems`
- Автоматический расчет `totalamount` на основе `subtotal` всех позиций
- Откат всех изменений при возникновении ошибки

### Второй сценарий: изменение email клиента

Транзакция включает:
- Валидация формата email
- Проверка уникальности email
- Обновление записи в таблице `customers`
- Откат при ошибке

### Третий сценарий: добавление продукта

Транзакция включает:
- Валидация названия и цены
- Вставка записи в таблицу `products`
- Откат при нарушении ограничений

## Запуск проекта

1. Перейти в директорию проекта:

```bash
cd "project"
```

2. Запустить контейнеры:

```bash
docker compose up --build
```

3. Наблюдать вывод в консоли - будут показаны результаты выполнения всех сценариев

## Остановка сервисов

```bash
docker compose down
```

Для полной очистки включая volumes:

```bash
docker compose down -v
```

## Полная переинициализация

```bash
docker compose down -v
docker compose up --build
```

## Начальные данные

База данных автоматически инициализируется скриптом `docker/init.sql`:
- 3 клиента в таблице `customers`
- 3 товара в таблице `products`

## Настройка логирования

Формат логов:

```
timestamp | level | logger | message
```

Уровень логирования задается через переменную окружения `LOG_LEVEL` (по умолчанию INFO).

## Переменные окружения

Основные параметры:

- `DB_HOST` - хост базы данных
- `DB_PORT` - порт
- `DB_NAME` - имя базы
- `DB_USER` - пользователь
- `DB_PASSWORD` - пароль
- `DB_POOL_SIZE` - размер пула соединений
- `DB_MAX_OVERFLOW` - максимальное переполнение пула
- `DB_POOL_TIMEOUT` - таймаут пула
- `DB_CONNECT_RETRIES` - количество попыток подключения
- `DB_CONNECT_RETRY_DELAY_SEC` - задержка между попытками

Значения по умолчанию находятся в `app/config.py`.

## Реализация транзакций

Транзакции реализованы с использованием контекстного менеджера `with session.begin():` в файле `app/transactions.py`. При выходе из контекста без исключений выполняется commit, при возникновении исключения - rollback.

## Обработка ошибок

Все транзакции имеют обработку исключений:
- При ошибке выполняется `session.rollback()`
- Ошибки логируются
- Исключения пробрасываются выше для обработки

## Проверка результатов

После каждого сценария выполняются SELECT-запросы для отображения состояния таблиц:
- `orders`
- `orderitems`
- `customers`
- `products`
